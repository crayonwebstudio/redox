# Redox WordPress version, converted to Astro

Static Astro 5 build of the Redox WordPress theme (version 1.0.6) light demo,
converted from the theme's demo export. No WordPress, PHP, or builder runtime
is shipped: page markup comes from the demo's pre-rendered page content, with
custom widgets re-rendered from their settings. See scripts/build-manifest.json
for the page list, widget counts, and approximations.

## Build

```sh
npm install
npm run build
```

Output goes to `dist/`. Serve with nginx using nginx.conf (same proven pattern
as the earlier HTML build: try_files $uri $uri/ $uri.html, no server-level
.html rewrites, custom 404 via error_page).

## Pages

- Homepage at `/` uses the digital-agency page content. `/digital-agency/`
  carries the same content but is noindex with canonical `/`.
- Kept pages: about-us, contact, digital-agency, digital-agency-classic,
  digital-agency-modern, faq, journals, marketing-agency, portfolio,
  portfolio-details, portfolio-st-2 through portfolio-st-6, service,
  services-details, services-st-2 through services-st-6, team, team-details.
- 14 blog posts at `/<post-slug>/`, listed from the journals page.
- The user's removal list (13 homepage variants, 7 portfolio effect pages,
  elementor-test) is not built and returns the custom 404.

## Regenerating content

`scripts/build.py` regenerates src/data/wp fragments and src/pages from the
demo export at ~/workspace/redox-wp-source. It downloads demo images into
public/assets/uploads on first run and skips existing files afterwards.

## Layout fix: generated per-element CSS

`public/assets/css/generated-layout.css` is generated by `scripts/build.py`
from the demo page settings (widths, flex, gaps, padding, margins,
backgrounds, borders, typography, positioning, per breakpoint, plus scoped
custom CSS). It is linked after the theme stylesheets in
`src/layouts/BaseLayout.astro`, and `npm run build` regenerates it first via
the `prebuild` script. Never hand-edit it or `dist/`; change the generator.
